Run it anywhere, including the closet

Calories is an Agent template you fork. Send a photo of your plate to a private Telegram bot and it replies with calories and protein, then saves the meal to your journal. One line in nuxt.config.ts decides which host runs it.

Clone the template Read the ViteHub docs

One meal, one round trip

  1. The phone sends a photo of breakfast.
  2. The Agent names each item and estimates grams, calories, and protein.
  3. The meal is written to a SQLite file on your disk, then read back.
  4. The reply drives home: 458 kcal, 20.4 g protein, $0.0021.

Text it, photograph it, or say it out loud

Send a meal to your private bot as a message, a photo, or a voice note. The Agent names each item, estimates the edible grams, then the calories and protein, and rates its confidence for the whole meal.

It tells you a meal is saved only after the database write succeeded and the row reads back. Every reply ends with a link to your dashboard and what that one reply cost in model usage.

Fix a meal by replying to it

Reply that was 3 eggs, not 2 and the meal and the day’s totals change. Reply asking to remove it and it leaves the journal.

Ask about your journal

How much protein this week? is answered from the saved meals, because the database is the record the Agent trusts.

Voice notes work too

The transcribe Capability turns a voice note into text first. The template uses Voxtral through OpenRouter.

Your data, your disk

Set the preset to node and Calories runs as a plain Node server on a box in the closet, a VPS, or a container. What it keeps lives on a disk you can back up with cp.

Meals in one SQLite file
Items, grams, calories, protein, and the totals sit in a SQLite file. Open it with any SQLite client.
Photos as files
Blob storage writes to the filesystem. The dashboard shows 768 px previews with camera metadata stripped, and the originals stay private.
A dashboard that only reads
The Nuxt dashboard shows totals and history. Changes happen in the chat.
One person can talk to it
The bot answers a single Telegram user ID, set as TELEGRAM_ALLOWED_USER_ID in .env.

The filesystem store serves one process. To run more than one instance, point Blob at S3-compatible storage.

Any channel, any model

The whole Agent is one file, server/agents/calories/agent.ts, about 100 lines, with a 28-line instructions.md prompt beside it. Three of its keys decide most of what you’d swap.

server/agents/calories/agent.ts, trimmedimport { defineAgent } from "vite-hub/agent";import { blob, db, transcribe, usage } from "vite-hub/agent/capabilities";import { telegram } from "vite-hub/agent/channels"; export default defineAgent({  capabilities: [    blob({ mode: "write" }), db({ mode: "write" }),    transcribe({ execute }), usage(),  ],  channels: {    telegram: telegram({      allowedUserIds: () => [env.telegram.allowedUserId],      botToken: () => env.telegram.botToken,    }),  },  driver: { model: () => openRouter("z-ai/glm-5.3-flashx") },});

capabilities

The Agent gets these four tools and nothing else: Blob files, the database, transcription, and usage, which prices each reply.

channels

Telegram is the example. Other adapters go in the same object.

  • Telegram
  • Discord
  • Slack
  • Teams
  • GitHub
  • HTTP
  • Web chat
  • Your own adapter

driver

GLM through OpenRouter by default. Any AI SDK model fits this line, and a coding harness such as Codex or Claude Code, or plain application code, can drive the Agent instead.

  • GLM
  • GPT
  • Claude

Moving hosts is a one-line diff

Change preset and keep the Agent. ViteHub gives the database, Blob storage, KV, auth, env, queues, workflows, schedules, and email the same API on each host, and backs them with that host’s own services.

Clone it, then pick a building

MIT licensed. You need Node.js 24.15+ and pnpm 10, an OpenRouter API key, and a Telegram bot token.

git clone https://github.com/vite-hub/calories.git
cd calories && pnpm install && cp .env.example .env
# add OPENROUTER_API_KEY, TELEGRAM_TOKEN, TELEGRAM_ALLOWED_USER_ID
pnpm db:migrate && pnpm dev

Once it runs, the local Console at /_vitehub lists recent Agent sessions, read-only.
